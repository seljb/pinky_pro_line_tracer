## 기준 버전과 새 범위

기존 `feat/line-alignment`의 기준 커밋은 `e658e29`입니다. 기준 버전에서는 오프라인 시험 16개와 좌·우 8cm의 이상적인 합성 정렬 두 조건이 통과한 결과가 기록돼 있습니다. 이는 실제 영상 품질·ROS 전송·실물 이동을 검증한 결과가 아닙니다.

새 작업은 별도 `feat/video-validation`에서 진행합니다. [브랜치 안내](BRANCH_WORKFLOW_KO.md)에 기능별 역할과 리뷰·통합 절차를 정리했습니다. 기존 브랜치와 `main`에 새 기능을 직접 덮어쓰지 않습니다.

## 기능별 검증 범위

| 기능 | 제공 범위 | 검증 근거와 제한 |
| --- | --- | --- |
| 픽셀 공간 선 관찰 | 고정/Otsu/적응형 마스크, ROI, 여러 행의 선 후보와 모호함 | 합성 입력 단위 시험과 실제 재생 출력으로 확인. 실물 최적값 확정 아님 |
| 저장 영상 재생 | 파일·이미지 폴더 입력, 프레임 CSV와 비교 결과 | 현재 실행의 입력·설정·프레임 수를 확인. 정확도에는 별도 정답 표시 필요 |
| 명령 게이트 | 활성화·소유권·새 요청·정지·시효 확인 | 소프트웨어 상태 시험. 실제 mux와 물리 비상정지 설치 아님 |
| 합성 명령 폐루프 | 합성 영상→검출→기존 정렬 제어기→게이트→이상적인 이동 | 현재 시나리오 로그와 종료 상태로 확인. 실제 로봇 성능 아님 |
| 기존 ROS 어댑터 | 카메라/odom/상태/서비스 연결 코드 | 실제 Jazzy 빌드·토픽·장비 확인 필요 |
| 직각 코너 | 모호한 관측의 감지·거부를 우선 검토 | 자동 코너 회전과 다음 선 재획득 완료로 해석하지 않기 |
| 내부 작업 이동 | 목표 식별·경로·작업 계약이 필요한 후속 범위 | 현재 위치 기준과 작업 인터페이스가 확정되지 않음 |

위 표는 기능 범위를 설명합니다. 최종 시험 개수와 통과·실패 여부는 실제 마지막 실행 결과와 작업 보고를 기준으로 확인합니다. 구현 파일이 있다는 이유만으로 실행 완료나 실물 검증 완료로 표시하지 않습니다.

### 이번 클라우드 실행에서 확인한 결과

- Python 3.12, Black 24.10.0: **189개 시험 통과**, Black 검사 통과.
- 합성 MJPG AVI 60프레임을 세 방식으로 재생하고, 각 방법의 CSV 60행과 저장 AVI 60프레임을 직접 다시 읽어 확인했습니다.
- 해당 합성 입력의 유효/무효 관측 수: fixed 30/30, Otsu 15/45, adaptive 30/30. 이는 이 장면과 설정에서의 관측 수이며 정확도·실물 우열이 아닙니다.
- `align_left`, `align_right`는 READY, `camera_dropout`은 FAILED와 출력 0, `operator_stop`은 IDLE과 정지 후 출력 0 조건을 통과했습니다.
- wheel을 빌드·설치한 뒤 checkout 밖에서 `video_replay`, `validation_run`, `closed_loop_sim`, `offline_demo`를 실행했습니다.
- 카메라 초기화 실패·종료 시험은 모의 객체 계약 시험입니다. 실제 ROS·카메라·모터·외부 mux는 미검증입니다.
- GitHub Actions 설정은 추가했지만 원격 실행 결과와 브랜치 보호·리뷰 설정은 확인하지 않았습니다.

모든 실행은 합성 자료를 사용했습니다. 사용자 사진은 요구사항 검토에 사용했으며 실제 Pinky 카메라 영상 처리 성능 시험을 수행했다고 기록하지 않습니다.

## 결과를 확인하는 명령

저장소 루트에서 오프라인 가상환경을 활성화한 뒤 실행합니다.

```bash
python -m black --check .
python -m pytest -q
bash scripts/verify_offline.sh
python -m pinky_line_alignment.validation_run \
  --output-dir /tmp/pinky-validation-status
```

출력 폴더는 기존 결과를 덮어쓰지 않도록 새 이름을 사용합니다. 영상 입력의 실행 예시는 [영상 검증 사용법](VIDEO_VALIDATION_KO.md)을 따릅니다.

| 결과 상태 | 기록 방법 |
| --- | --- |
| 실제 실행하고 기대 결과를 확인 | 실행 명령·결과·현재 산출물 위치를 함께 기록 |
| 실행 실패 | 오류와 진단을 남기고 통과로 계산하지 않음 |
| 실행하지 않음 | 미실시로 표시하고 필요한 환경 명시 |
| 건너뜀·비활성 시험 | 이유와 영향을 기록하고 통과와 구분 |
| 정답 없는 검출 결과 | 검출 개수·시각 확인 결과만 기록. 정확도 수치 생성 금지 |

원본 프레임의 실제 촬영 시각과 파일의 재생 시각, 처리 시간과 센서→모터의 종단 지연도 각각 다른 값입니다. 픽셀 오차에 임의의 계수를 곱해 실측 거리로 보고하지 않습니다.

## 실물에서 필요한 근거

- Pinky 장착 카메라의 원본 영상: 직선·좌우 코너·그림자·반사·이음새·선 손실.
- 카메라 높이·각도·해상도·노출과 실제 테이프 폭.
- 카메라 내부 보정과 영상→바닥 변환, 독립 검증점의 RMSE·최대 오차.
- 실제 카메라·`/odom`·속도 명령의 타입·경로·QoS·시각과 프레임 기준.
- 모터 방향·속도 응답·정지 동작, 실제 외부 mux와 독립 비상정지·낙하 방지 조건.
- 작업 지점·선 복귀 지점·최종 정차 위치를 식별할 마커 또는 측위 계약.

실물 확인은 모터 OFF 센서 확인부터 시작합니다. 합성 결과를 근거로 바로 모터를 활성화하지 않습니다. `handoff_ack` 성공과 실제 속도 명령 소유권 전환도 각각 검증해야 합니다.
