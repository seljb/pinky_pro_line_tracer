**모터 OFF 센서 확인부터 시작하고 보정·외부 mux·비상정지 검증 후에만 주행을 계획하세요.**

<a id="section-1"></a>

## 1. 장치와 ROS 확인 — 모터 명령 없이

- [ ] 보유 Pinky Pro, Ubuntu/ROS 2 버전, Python 버전 기록
- [ ] `ros2 topic list -t`로 카메라 이미지/`/odom`/`/cmd_vel` 실제 경로 확인
- [ ] 오도메트리의 좌표계(`odom`, `base_link`), 시각 및 회전 부호 확인
- [ ] 카메라 `frame.shape`, BGR/RGB 순서, 노출, 실제 프레임 시각과 FPS 기록
- [ ] IR 센서 3개의 방향·높이·흑백 응답·좌우 순서 확인 (IR은 현재 코드에서 미사용)
- [ ] 카메라/차체/차축 기준점 간 오프셋과 카메라 장착 높이·경사 측정

<a id="section-2"></a>

## 2. 카메라 보정 — 물리 바닥 좌표로

- [ ] 실제 해상도와 촬영 모드 고정
- [ ] 여러 자세의 체커보드로 K/D 보정 및 잔차 확인
- [ ] 왜곡 **보정된 영상 좌표**와 실제 바닥 x/y 대응점 6개 이상 측정
- [ ] 적어도 5개의 **보정에 사용하지 않은 독립 점**으로 RMSE와 최대 오차 측정
- [ ] 실물에서 검증한 값만 `real_calibration.json`으로 보관 (해당 파일은 `.gitignore` 적용)
- [ ] 좌·우·근거리·원거리에서 선 검출 영역과 시야 밖 조건 확인

<a id="section-3"></a>

## 3. 모터 OFF 상태에서 인식/진단만 테스트

- [ ] 카메라와 odom을 수신할 때 오류 없이 `/line_align/status`가 갱신되는지
- [ ] 선이 보이면 `lateral_m`, `heading_deg`가 물리 방향과 맞는지
- [ ] 선이 없는 영상, 그림자, 번짐, 교차로에서 잘못된 선을 선택하지 않는지
- [ ] 프레임 시간/센서 시간 오류·해상도 불일치 때 정지/실패하는지
- [ ] 모터 제어는 `allow_drive:=false`로 유지

<a id="section-4"></a>

## 4. 나중에 실제 주행을 검증하려면

- [ ] 실제 검증된 구동 속도/모터 방향/엔코더와 독립 E-stop
- [ ] 작업 공간·낙하·회전 반경·장애물 제거, 사람이 로봇 가까이 접근하지 않는 조건
- [ ] **외부** 안전 인터록 및 `/cmd_vel` mux 설치; 정렬과 선 추종의 동시 구동 금지
- [ ] 브리지/토픽 지연 상한 실측. `get_frame()`의 수신 시각은 카메라 촬영 시각이 아닐 수 있음
- [ ] 차체를 띄운 회전 방향 시험 → 지상 저속 단일 구간 시험 순서
- [ ] READY 이후 센서가 끊겼을 때 인계 거부되는지 확인
- [ ] 여러 시작 위치·각도·조명 조건에서 성공률과 재시도/오완료를 기록

<a id="section-5"></a>

## 5. 로깅 규칙

`logs/experiment_template.csv`를 복사해 시험마다 환경·시작 자세·예상값·실제값·실패 유형을 남긴다. 시뮬레이션 결과는 실물 데이터와 합쳐서 보고하지 않는다.
